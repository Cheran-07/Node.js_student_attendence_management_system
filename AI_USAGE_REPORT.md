**AI OUTPUT THAT WAS WRONG:**
Two separate issues surfaced during development and real-world testing:
1. *(Dev-environment only, not shipped)* While testing locally, background server processes
   launched with `node ... &` inside one shell command were not surviving into the next shell
   command, so `curl` calls to test the API kept returning connection errors even though the
   server had printed its "running" message moments earlier.
2. *(Real install failure, on the actual submission)* The initial version used `better-sqlite3`,
   a native C++ addon, as the database driver. On a Windows machine with Node 24 and no Visual
   Studio Build Tools installed, `npm install` failed outright with a `node-gyp`/MSVS error
   (`Could not find any Visual Studio installation to use`) — meaning the project wouldn't even
   install for a grader without a full C++ build toolchain, which is a real installability defect,
   not just a dev-machine quirk.

**HOW I IDENTIFIED THE PROBLEM:**
1. Checked the server log file (it showed the server had started and then apparently stopped) and
   ran `ps aux | grep node` right after a "successful" start, which showed no Node process
   actually running — confirming the process wasn't surviving past the end of its shell command.
2. The `npm install` error log on Windows pointed directly at `node-gyp rebuild` failing inside
   `node_modules/better-sqlite3` with a missing Visual Studio installation — a classic
   native-addon compilation failure, not an application bug.

**HOW I FIXED IT:**
1. Restarted the dev server using `setsid` with input redirected from `/dev/null` so it fully
   detaches from the parent shell and survives across separate commands, then re-ran the same
   `curl` smoke tests to confirm it was a process-supervision issue, not an app bug.
2. Replaced `better-sqlite3` with Node's **built-in** `node:sqlite` module (stable without a CLI
   flag since Node 22.5+), which needs zero native compilation since it ships inside the Node
   binary itself. This removed the dependency entirely and cut the install from ~118 native
   packages to ~83 pure-JS ones. Since `node:sqlite`'s `DatabaseSync` has no built-in
   `.transaction()` convenience method the way `better-sqlite3` does, I added a small
   BEGIN/COMMIT/ROLLBACK wrapper with the same call shape so the rest of the codebase didn't need
   to change. Re-ran the full test suite afterward (login for both roles, marking attendance
   inside a transaction, a within-window correction updating the audit log, the low-attendance
   report, and static file serving) to confirm everything still worked identically on the new
   driver.
